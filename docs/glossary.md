## 1. 일하는 방식 (애자일)

**애자일(Agile)** = 처음부터 완벽한 계획을 세우지 않고, **짧게 해 보고 → 확인하고 → 고치기**를 반복하는 방식입니다.

> 📚 시험 공부로 치면: 3주 계획을 한 번에 다 짜는 대신, **2~3일 공부 → 모의고사 → 약한 부분 보충**을 반복하는 것.

| 용어 | 쉬운 뜻 | 📚 시험 공부 비유 | 🤖 우리 프로젝트에서 |
|---|---|---|---|
| **스프린트** | 2~3일짜리 짧은 작업 기간 | "이번 2~3일엔 1~3단원" | S1(11/26~28) … S7(12/15~17), 7번 |
| **Milestone** (마일스톤) | 큰 단계의 마감 | "1주차 끝까지 수학 1회독" | M1 기술 검증(12/02) … M5 발표(12/18) |
| **백로그** | 앞으로 할 일 전체 목록 | 공부할 단원 전체 목록 | GitHub [Issues](https://github.com/Gansoolgo/Thursday/issues) 전체 |
| **Issue** (이슈) | 할 일 카드 한 장 | "3단원 문제 풀기" 포스트잇 | #3 로봇 연결, #6 언어 모델 시험 등 |
| **유저 스토리** | 사용자 입장에서 쓴 기능 설명 | — | "작업자로서 '저항 줘' 하면 받고 싶다" (US-03) |
| **인수 조건 / 완료 조건** | 그 일을 "다 했다"고 인정하는 기준 | "20문제 중 18개 맞으면 통과" | Issue의 ⑤칸 체크박스 |
| **DoD** (완료 기준) | **모든** 작업에 공통인 "완료" 조건 | "채점까지 해야 끝난 것" | PR 체크리스트 + CI 통과 |
| **칸반 보드** | 할 일 / 하는 중 / 끝남을 칸으로 나눈 판 | 포스트잇을 칸별로 붙인 벽 | [스프린트 보드](https://github.com/orgs/Gansoolgo/projects/1) |
| **spike** (기술 검증) | 되는지 안 되는지 **짧게 시험**해 보는 일 | "이 문제집이 나한테 맞나 하루만 풀어 보기" | M1의 #3~#7, #29, #30 |
| **GO / NO-GO** | 계속할지, 다른 방법으로 바꿀지 판정 | "모의고사 70점 넘으면 계속, 아니면 공부법 바꾸기" | 12/02 회의 |
| **데일리** | 매일 짧게 진행 상황 공유 | 스터디원끼리 "어제 뭐 했어?" | Discord에 한 줄 |
| **스프린트 리뷰** | 스프린트 끝에 결과 보여 주기 | 모의고사 결과 같이 보기 | 실제 로봇으로 시연 |
| **회고** | 일하는 **방식**을 돌아보기 | "밤샘보다 아침 공부가 나았다" | 잘된 점 / 아쉬운 점 / 바꿀 점 |
| **증분** | 스프린트마다 새로 생긴, 실제로 돌아가는 결과물 | 이번에 새로 풀 수 있게 된 단원 | main에 합쳐진 기능 |
| **벨로시티** | 한 스프린트에 실제로 끝낸 양 | "2~3일에 단원 3개 하더라" | 스프린트마다 닫은 Issue 수 |
| **PO** (Product Owner) | 무엇을 먼저 할지 정하는 사람 | 스터디 리더 | 팀 회의에서 결정 |
| **핵심 경로** | 늦어지면 **전체가** 늦어지는 일들의 줄 | 수학을 못 끝내면 물리도 못 함 | #3 → #4 → #8 → 공통 타입 → … ([dependencies.md](plan/dependencies.md)) |
| **Plan B** (대비책) | 원래 방법이 안 될 때 쓸 다른 방법 | 문제집이 안 맞으면 인강으로 | 위험마다 정해 둠 ([dependencies.md](plan/dependencies.md) 2장) |

## 2. Git · GitHub

> 💾 게임 저장으로 비유하면 쉽습니다.

| 용어 | 쉬운 뜻 | 💾 비유 |
|---|---|---|
| **저장소** (Repository) | 프로젝트 파일 전체를 담은 곳 | 게임 세이브 폴더 |
| **main** | 모두가 함께 쓰는 **원본** | 공식 세이브 파일 |
| **브랜치** | 원본을 건드리지 않고 따로 작업하는 **복사본 공간** | 세이브를 복사해서 따로 플레이 |
| **커밋** | 작업 중간 **저장 버튼** (메모 포함) | 세이브 포인트 |
| **push** (푸시) | 내 컴퓨터의 커밋을 GitHub에 **올리기** | 클라우드에 세이브 업로드 |
| **pull** (풀) | GitHub의 최신 내용을 내 컴퓨터로 **받기** | 클라우드 세이브 내려받기 |
| **PR** (Pull Request) | "제 작업을 원본에 합쳐 주세요" **요청서** | "내 플레이 기록을 공식 세이브에 반영해 주세요" |
| **병합** (Merge) | 요청을 받아들여 원본에 **합치기** | 공식 세이브에 반영 |
| **Squash and merge** | 커밋 여러 개를 **하나로 묶어서** 합치기 | 세이브 포인트 10개를 하나로 정리해서 반영 |
| **충돌** (Conflict) | 두 사람이 같은 곳을 다르게 고쳐서 생기는 문제 | 둘이 같은 캐릭터를 다르게 키움 → 하나를 골라야 함 |
| **CI** | PR을 올리면 **자동으로 검사**해 주는 기능 (초록 = 통과) | 저장할 때 자동 오류 검사 |
| **리뷰** | 다른 팀원이 PR을 읽고 의견을 주는 것 | 친구가 내 플레이를 봐 주기 |
| **Draft PR** | "아직 덜 됐지만 봐 주세요" PR | 중간 저장본 보여 주기 |
| **main 보호 규칙** | main에 바로 저장 못 하게 막는 설정 | 공식 세이브는 검사 통과해야만 덮어쓰기 가능 |

## 3. 우리 프로젝트 기술 용어

| 용어 | 쉬운 뜻 |
|---|---|
| **Edge AI** (엣지 AI) | 인터넷(클라우드)에 보내지 않고 **현장 기기에서** AI를 돌리는 것. 우리는 노트북 한 대 |
| **소형 언어 모델 (sLM)** | ChatGPT 같은 언어 모델의 **작은 버전**(30~40억 개 파라미터). 노트북에서 돌아감. 사용자 말을 로봇 할 일 목록(JSON)으로 바꿈 |
| **LLM** | 대형 언어 모델. 문서에서 "로컬 LLM"은 노트북에서 돌리는 소형 모델을 뜻함 |
| **JSON** | 컴퓨터끼리 주고받는 정리된 글 형식. 예: `{"skill": "hand_over", "object_id": "resistor"}` |
| **Skill** | 로봇이 할 수 있는 동작 하나 (집어 옮기기, 건네기, 확인하기) |
| **World State** | 카메라로 본 **지금 작업대 상태** (어느 칸에 무엇이 있나, 로봇은 뭐 하나) |
| **Safety Gate** | 언어 모델이 낸 계획을 **실행 전에 검사**하는 관문. 위험하거나 이상하면 막음 |
| **IK** (역기구학) | "손끝을 여기 보내려면 관절을 각각 몇 도 돌려야 하나" 계산 |
| **티칭** | 사람이 로봇을 직접 움직여 자세를 저장해 두고, 나중에 그대로 재생 |
| **보정** (캘리브레이션) | 카메라 화면 위치(픽셀)와 로봇 위치(mm)를 맞추는 작업 |
| **mock** (목) | 진짜 로봇·카메라 대신 쓰는 **가짜**. 로봇 없이도 코드를 시험할 수 있게 함 |
| **NPU · iGPU · CPU** | 노트북 안의 계산 장치 3종. NPU = AI 전용(저전력), iGPU = 그래픽·병렬 계산, CPU = 일반 계산 |
| **OpenVINO** | Intel의 AI 실행 도구. 모델을 Intel 칩에서 빠르게 돌림 |
| **Geti** | Intel의 물체 인식 모델 학습 도구 (사진에 표시 → 학습) |
| **Whisper** | 음성을 글자로 바꾸는 AI 모델 |
| **tok/s** | 언어 모델이 1초에 만들어 내는 글자 조각 수. 클수록 빠름 |
| **TOPS** | AI 칩 성능 숫자 (1초에 조 단위 계산 횟수). 칩마다 측정 방식이 달라 직접 비교는 어려움 |
| **Hailo · AI HAT** | 라즈베리파이에 붙이는 AI 가속 부품. 우리는 확장 옵션으로만 |
| **양자화** (INT4 · INT8) | 모델 숫자를 줄여 더 작고 빠르게 만드는 것. 정확도가 약간 떨어질 수 있음 |
| **헝가리안 알고리즘** | "물건 N개를 칸 N개에 가장 효율적으로 배정"하는 계산 방법. 정리 최적화에 사용 |
| **95% 신뢰구간** | "20번 중 18번 성공"을 "90% (69~97%)"처럼 범위로 쓰는 것. 적은 횟수로 과장하지 않으려고 |
