# 비전과 문제 정의

> **📌 3줄 요약**
> - **문제:** 손으로 하는 작업에는 찾기·꺼내기·치우기 같은 부수 작업이 붙어 흐름이 끊긴다 (교사에게는 더 몰린다).
> - **가설:** 새 작업은 설명서만 추가하면 되고(H1), 처음 보는 목표도 처리하며(H2), 사용 기록 기반 정리가 꺼내는 시간을 줄인다(H3).
> - **범위:** 모형 물건으로 하는 개념 증명. 상용 품질·실제 공구·움직이는 손 따라가기는 하지 않는다.
> 📖 낯선 말은 👉 [용어집](glossary.md)

## 제품 비전 (한 문장)

**작업하는 사람이 물건을 찾고 꺼내고 치우는 일에 신경 쓰지 않고 작업 자체에 집중하도록, 옆에서 준비·보조·정리를 해 주는 오프라인 AI 조수 로봇팔.**

## 문제

손으로 하는 작업(전자회로 실습, 조립, 공예, 실습 수업)에는 본 작업 말고도 반복되는 부수 작업이 붙습니다.

- **작업 전:** 필요한 부품·도구를 찾아 꺼내 놓는다. 빠진 게 있으면 작업 도중에 알게 된다.
- **작업 중:** 손이 바쁠 때 필요한 물건을 다시 찾아야 한다. 흐름이 끊긴다.
- **작업 후:** 정리한다. 그런데 보통 "늘 하던 자리"에 두기 때문에, 다음 작업에서 자주 쓰는 물건이 멀리 있을 수 있다.

교육 현장에서는 같은 일이 교사에게 몰립니다. 실습 수업마다 교구를 준비하고, 수업 중 학생들에게 나눠 주고, 끝나면 정리합니다.

> 위 불편은 팀의 실습 경험에서 나온 **가설**입니다. 실제 사용자(실습실 학생·교사) 인터뷰로 확인할 예정입니다.

## 기존 방식과 한계

| 기존 방식 | 한계 |
|---|---|
| 사람이 직접 준비·정리 | 반복적이고, 작업 흐름이 끊김 |
| 정해진 동작만 하는 자동화(프리셋) | 작업 종류가 바뀔 때마다 사람이 새로 프로그래밍해야 함 |
| 클라우드 LLM + 로봇팔 공개 프로젝트 | 인터넷 필요, 성공률 등 정량 평가가 거의 없음 |

## 개선 가설

- **H1 (새 작업 추가 비용):** 새 작업 종류를 추가할 때, 규칙 기반은 동작 코드를 새로 짜야 하지만 우리 방식은 **작업 설명서(텍스트)만 추가**하면 된다. → 추가에 걸린 시간과 엔진 코드 수정 줄 수로 비교.
- **H2 (처음 보는 목표):** 미리 정하지 않은 목표를 줘도, 등록된 물건·Skill 범위 안이면 계획하고 수행한다. 범위 밖이면 안전하게 거절하거나 되묻는다. → 계획 실패와 실행 실패를 나눠 성공률 측정.
- **H3 (최적 정리):** 사용 기록 + 공간 효율을 합친 배치가 고정 위치 정리보다 다음 작업에서 꺼내는 시간·팔 이동 거리를 줄인다. → 같은 작업 순서로 비교.
- **H4 (능동 보조):** 작업 단계를 추정해 다음 물건을 먼저 제안하고, 다 쓴 물건을 수시로 정리하면, 사람이 직접 시켜야 하는 명령 수가 줄어든다. → 단계 추정 정확도, 제안 적중률, 사람이 말한 명령 수.
- **H5 (안전):** 위험하거나 범위 밖인 요청은 모두 거절하고, 정상 요청은 거의 막지 않는다. → 거절률, 잘못된 거절률.

> 측정 방법·횟수·비교군은 [평가 계획](plan/evaluation.md)에 있습니다.

## 대상 사용자

- **1차:** 작업대에서 순서가 있는 조립 작업을 하는 사람 — 실습하는 학생·메이커. (시연은 블록 작업으로 과정 인식을 보여 줌, D-14)
- **2차:** 실습 수업을 준비하는 교사, 생활 작업(빨래 개기 등)을 돕는 경우 (같은 엔진으로 지원).

## 성공 기준 (수치는 M1 실측 후 확정)

- 같은 엔진으로 **서로 다른 작업 2가지**(블록 작업, 손수건 개기)를 시연. 블록 작업은 순서 이탈을 알아채고 묻는 과정 인식을 보여 줌. 손수건은 매번 다른 초기 상태를 판단해 필요한 단계만 수행.
- 단계별 반복 시험(약 20회) 성공률 기록.
- 정리 전후 꺼내는 시간·팔 이동 거리 변화, 규칙 기반 정리와 비교.
- 위험하거나 범위 밖 요청은 실행하지 않음(차단율 기록).
- 인터넷 없이 Intel 노트북 한 대에서 동작.

## 하지 않을 것 (Out of scope)

- 상용 제품 수준의 품질, 안전 인증, 내구성 — **개념 증명 프로토타입**입니다.
- 실제 공구(칼, 인두 등) 사용. 가벼운 모형·블록·천만 다룹니다.
- 실제 회로 조립(브레드보드 등)과 그 조립 상태 인식. 블록 평면 배치로 과정 인식만 보여 줍니다 (D-14).
- 블록 수직 쌓기 인식 (아래 블록이 가려짐).
- 움직이는 손을 계속 따라가며 건네기. 건넴 구역에 멈춘 손 위에만 놓고, 손이 없으면 정해진 칸에 놓습니다 (D-08).
- 임의로 구긴 천 펴기. 손수건은 모서리 한두 개가 접힌 상태까지만 다룹니다 (D-07).
- 자율주행차 연동, SmolVLA, 팬틸트 조명 (시간이 남으면 확장).
- 검증하지 않은 "최초", "최적" 같은 주장.

## 가장 불확실한 가정 (M1에서 먼저 검증)

1. SO-101 + IK로 정해진 칸 사이 pick/place가 안정적으로 되는가 (좌표 보정 오차 포함).
2. 노트북 iGPU에서 로컬 LLM이 쓸 만한 속도로 올바른 JSON 계획을 내는가.
3. 깊이 카메라(HP60C)의 컬러 영상으로 블록 6색과 트레이·손수건 상태를 안정적으로 구분하는가. 블록 6개 + 트레이를 팔이 들 수 있는가.
4. Windows 11 노트북에서 LeRobot(SO-101 연결·IK)과 OpenVINO가 함께 문제없이 동작하는가. (LeRobot·Intel physicalai 공식 예제는 Linux 중심이라 Windows 지원 수준이 문서로 확인되지 않음) **양팔 SO-101 구성 지원도 함께 확인.**
5. SO-101 그리퍼로 테이블 위 천 모서리를 집을 수 있는가, 양팔로 펴고 접을 수 있는가 (D-07).
6. 깊이 카메라로 건넴 구역의 손 3D 위치를 손 위에 놓을 만큼 정확히 읽는가 (D-08). HP60C 2대를 Windows에서 같이 켜도 깊이가 깨지지 않는가 (D-15).
