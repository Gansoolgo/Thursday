# 기록 가이드 — 무엇을, 어디에, 어떻게 남기나

> **📌 3줄 요약**
> - 이 프로젝트는 **"숫자로 증명"** 이 핵심이라 **기록이 곧 결과물**입니다. 실패한 시도도 남깁니다.
> - 시험하면 **실험 기록**, 사진·녹음을 모으면 **데이터 카드**, M1 숫자는 **results-m1.md** 에 씁니다. 양식은 복사해서 쓰면 됩니다.
> - 큰 파일(사진·영상·녹음·모델)은 **팀 공유 폴더**에, 저장소에는 **어디 있는지와 설명만** 적습니다.
> - **까먹지 않게:** AI가 작업 끝에 기록 초안을 만들고(AGENTS.md), PR 체크리스트와 Issue 완료 조건에 기록 항목이 들어 있습니다.
> 📖 낯선 말은 👉 [용어집](glossary.md)

## 2. 기록할 때 지킬 것 5가지

1. **숫자로 쓴다.** "잘 됨" ❌ → "20번 중 17번 성공, 평균 3.2초" ✅
2. **실패도 쓴다.** 안 된 방법과 이유가 다음 사람의 시간을 아낍니다. 발표 질문 대비도 됩니다.
3. **조건을 쓴다.** 날짜, 장치(CPU/GPU/NPU), 모델·버전, 조명, 전원 연결 여부. 조건이 없으면 숫자를 비교할 수 없습니다.
4. **그날 쓴다.** 나중에 쓰면 잊습니다. 5분이면 됩니다.
5. **결론과 다음 할 일로 끝낸다.** "그래서 무엇을 정했나 / 다음에 무엇을 하나"

## 3. 큰 파일은 공유 폴더에

| 종류 | 저장소에 | 공유 폴더에 |
|---|---|---|
| 학습 사진, 녹음 | ❌ | ✅ 원본 |
| 시험 영상, 사진 | ❌ (작은 사진 1~2장은 Issue·PR 댓글에 첨부 가능) | ✅ 원본 |
| 모델 파일 (`.bin` `.xml` `.onnx`) | ❌ (.gitignore가 막음) | ✅ |
| 위 파일들의 **설명** | ✅ 데이터 카드·실험 기록 | — |

**공유 폴더 구조 (안):**

```text
Thursday 공유 폴더/
├── data/            # 학습용 사진·녹음 (데이터 카드 이름과 같은 폴더명)
│   ├── objects_v1/
│   └── voice_ko_v1/
├── models/          # 학습·변환한 모델 (버전별)
├── videos/          # 시험·시연 영상 (날짜_내용.mp4)
└── photos/          # 작업대·실패 장면 사진
```

> 📁 **공유 폴더: 구글 드라이브 `Thursday 공유 폴더`** (11/27 생성). 이 저장소는 공개라서 **링크는 여기에 적지 않습니다.** 팀원에게만 따로 공유하며, 안 열리면 신재석에게 초대를 요청하세요.

## 4. 개인정보

- 녹음·영상에는 **본인 동의를 받은 팀원만** 나오게 합니다. 팀원 외 사람은 넣지 않습니다.
- 데이터 카드에 동의 여부를 적습니다.
- 저장소에는 얼굴 사진·음성 원본을 올리지 않습니다.
