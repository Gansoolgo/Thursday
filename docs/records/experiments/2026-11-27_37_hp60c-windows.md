# 실험 기록: HP60C 깊이 카메라를 Windows 노트북에서 열기

- **날짜:** 2026-11-27
- **작성자:** (확인 필요) — Claude Code 초안
- **관련 Issue:** #37
- **결과 한 줄:** ✅ 성공 (카메라 1대) — Windows에서 Python으로 컬러 640×480 + 깊이 640×480(mm)을 약 10 fps로 받음. 두 대 동시·간섭은 아직

## 1. 목적
HP60C를 Windows 노트북에서 Python으로 컬러·깊이 모두 읽을 수 있는지 확인한다 (#37 완료 조건 1).

## 2. 환경
| 항목 | 값 |
|---|---|
| 장치 | Intel Core Ultra 5 225H 노트북 |
| OS | Windows 11 Pro (10.0.26300) |
| 주요 버전 | Python 3.12, OpenCV 5.0.0, Angstrong Viewer V2.1.10_240109 |
| 카메라 | HP60C 1대 (Windows 장치 이름 `ASJ ZNX_NVT`, USB `VID_3482 PID_6723`) |
| 하드웨어 상태 | 노트북에 직접 연결 (허브 사용 여부 확인 필요), 거치 전 |

## 3. 방법
시험 스크립트는 저장소 밖 `sim/` 폴더에 있음 (`camera_view.py`, `probe_camera.py`, `probe_raw.py`).

```powershell
python camera_view.py --list                 # 카메라 번호 확인
python probe_raw.py 1                        # 열기 방식별 원본 데이터 확인
python camera_view.py --cam 1 --board 600x450
```

깊이: 판매처(Yahboom) 드라이브의 `Windows Software.zip` → `Angstrong Viewer V2.1.10_240109.7z`를 영어 경로(`C:\hp60c`)에 풀고 `AngstrongViewer.exe` 실행.

## 4. 결과

| 조건 | 결과 | 메모 |
|---|---|---|
| OpenCV `CAP_DSHOW`로 열기 | ❌ 검은 화면 | 프레임은 오지만 값이 전부 0 |
| OpenCV `CAP_MSMF`로 열기 | ✅ 컬러 | 640×642, NV12, 3초에 35~50프레임 (fps 정밀 측정 안 함) |
| 해상도 지정 (1280×720 등) | ❌ 프레임 없음 | 해상도를 지정하지 않아야 나옴 |
| OpenCV로 깊이 | ❌ | 일반 카메라 방식으로는 컬러 한 종류만 보임 |
| **제조사 뷰어(AngstrongViewer)** | ✅ **깊이 나옴** | 사용자가 화면으로 확인. 수치 측정은 안 함 |
| 뷰어 파일 백신 검사 | ✅ 이상 없음 | Windows Defender. 디지털 서명은 없음 |
| **SDK DLL + 직접 만든 C++ bridge** | ✅ **컬러·깊이 둘 다** | 컬러 640×480 BGR, 깊이 640×480 uint16(mm), IR 1280×720. bridge 12~13 fps, Python 약 10 fps |
| Python으로 읽은 깊이 값 (거치 전, 책상 위 임의 방향) | ✅ | 유효 픽셀 61.8%, 최소 364 / 중앙 2172 / 최대 4089 mm |
| 이미 꽂혀 있는 카메라 찾기 | ❌ | `AS_SDK_GetCameraList` "No device found". **뽑았다 다시 꽂으면** 감지되어 정상 동작 |

- 뷰어 폴더에 Windows 64비트 SDK `AngstrongCameraSdk.dll`이 있음. Linux SDK와 같은 함수(`AS_SDK_StartListener`, `AS_SDK_OpenCamera`, `AS_SDK_RegisterStreamCallback` 등, C++ 방식)를 내보냄.
- 사진·영상: (확인 필요)

## 5. 잘 안 된 것과 원인
- **검은 화면:** DSHOW 방식으로 열면 값이 전부 0. MSMF로 바꾸니 해결.
- **창이 안 꺼짐:** 한글 입력 상태에서 `q`가 `ㅂ`으로 들어가 종료 키가 안 먹음 → ESC·창 X 버튼으로도 종료되게 수정. 프레임을 못 읽는 동안 창이 "응답 없음"이 되어 프로세스가 카메라를 계속 잡는 문제도 있었음 → 수정.
- **깊이를 Python으로 못 받음:** SDK가 C++ 방식(`std::list` 등)이라 Python `ctypes`로 바로 부를 수 없음. 작은 C++ 연결 프로그램이 필요 (Linux용은 외부 저장소 `th2102da/hp60c-camera`의 `shm_bridge`가 있음, private).

## 6. 결론과 다음 할 일
- **결론:** Windows 노트북에서 HP60C **컬러·깊이를 Python으로 받을 수 있다.** 뷰어에 들어 있는 Windows SDK DLL에 C++ bridge(외부 저장소 `th2102da/hp60c-camera`의 Linux 판을 옮김, Visual Studio Build Tools로 빌드)를 붙이고 Windows 공유 메모리로 넘긴다. D-06(Windows) 유지 가능.
- **다음:**
  1. 이미 꽂힌 카메라를 다시 꽂지 않고 찾는 방법 (지금은 다시 꽂아야 함).
  2. HP60C 두 대 동시 연결과 적외선 간섭 시험 (#37 나머지 조건). bridge는 지금 1대만 다룸.
  3. 정면 60~70cm, 측면 40~50cm 위치에서 화면 확인.
- results-m1.md / decisions.md 반영: 안 함 (확인 후)
